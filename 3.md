## 🔑 Configuração das chaves

No topo do `<script>` do `index.html`:

```js
const SUPABASE_URL      = "__SUPABASE_URL__";       // https://SEU-PROJ.supabase.co
const SUPABASE_ANON_KEY = "__SUPABASE_ANON_KEY__";  // chave anon/public
```

- Substitua os dois placeholders pelos valores do seu projeto
  (**Project Settings → API**).
- ⚠️ **Somente a chave `anon/public`** vai no front-end. A **`service_role`
  NUNCA** entra no HTML nem no repositório — ela é secreta e concede acesso total
  ignorando a RLS. Use-a apenas em rotinas de servidor/admin, fora deste app.

`.env.example` (para referência/CI):
```
SUPABASE_URL=https://SEU-PROJ.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJ...
```

## 👤 Criar o usuário administrador (passo manual, seguro)

1. Supabase → **Authentication → Users → Add user**
2. E-mail: `adm@br.nestle.com` · defina uma **senha provisória**
3. (Opcional) marque "Auto Confirm User" para pular verificação de e-mail
4. No **primeiro login** no app, oriente o ADM a **trocar a senha** em
   "Esqueci minha senha" (envia link) — ou troque pelo painel.
5. O trigger `handle_new_user` já promove esse e-mail a **admin/aprovado**
   automaticamente e o roteia direto ao Dashboard Executivo.

> Os 11 consultores da planilha estão na *allowlist* (`consultores_autorizados`):
> ao criarem conta com o mesmo e-mail, entram **aprovados** e já recebem suas
> fazendas vinculadas. Novos e-mails ficam **pendentes** até o ADM aprovar.

## 🚀 Deploy no Vercel (passo a passo)

1. **Suba o repositório** no GitHub (público ou privado — tanto faz).
2. Vercel → **Add New… → Project → Import** o repositório.
3. **Framework Preset:** *Other* (é HTML estático, sem build).
   - Build Command: *(vazio)* · Output Directory: `.` (raiz)
4. **Deploy.** O Vercel publica o `index.html` na raiz.
5. **Chaves:** como é estático puro, o mais simples é **preencher as duas
   constantes** no `index.html` antes do commit. (A `anon key` é pública por
   design, então pode ir no bundle do front.)
   - Se preferir não versionar as chaves, gere o `index.html` num passo de build
     que substitua `__SUPABASE_URL__`/`__SUPABASE_ANON_KEY__` por
     `process.env...` — posso te entregar esse script se quiser.
6. **Supabase → Authentication → URL Configuration:** adicione a URL do Vercel
   (ex.: `https://seu-app.vercel.app`) em **Site URL** e **Redirect URLs**,
   para o fluxo de redefinição de senha funcionar.

## ✅ Funcionalidades entregues

- **Auth + perfis** (`consultor`/`admin`) com roteamento e **aprovação pelo ADM**.
- **RLS no banco**: consultor só vê suas fazendas/visitas; visitas **imutáveis**
  (sem UPDATE/DELETE); admin com leitura global.
- **Fluxo do consultor**: seleção/cadastro de fazenda em campo, **CRUD de talhões
  com área (ha) obrigatória**, formulário de visita completo (observações
  dinâmicas, nutrição com **cálculo automático de NPK e micros**, CPD, herbicidas,
  observações por bloco).
- **Continuidade** entre visitas (checkboxes de adesão do produtor).
- **Evidências**: foto + **data/hora/GPS**; a **foto não vai ao Supabase** (só os
  metadados) — exportação direta pelo dispositivo.
- **Histórico** somente leitura.
- **Exportações**: **PDF** (seleção de seções, nome
  `AAMM_CONSULTOR_RV_PRODUTOR_FAZENDA`), **fotos** e **XLSX** (Power Query/BI).
- **Dashboard Executivo** (admin): filtros globais, KPIs, gráficos (visitas/mês,
  ranking, observações, adesão, NPK por fazenda), fazendas não visitadas com
  **alerta > 30 dias**, e export **PDF + XLSX**.
